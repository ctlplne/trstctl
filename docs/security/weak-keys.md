# Weak keys

A key can be weak whatever its algorithm and size. In October 2026 eight
eMudhra intermediate CAs turned out to have P-384 private keys that were small
integers (4, 56, 66, 115, 155, 156, 230 and 237): anyone could compute them
from the public key. trstctl checks every public key it rates for that kind of
structural weakness, not only for its size.

## The checks

The checks live in `internal/crypto/weakkey` and are modeled on the badkeys
project (badkeys.info, MIT licence). They are re-derived from the published
definitions; no badkeys code or data is copied.

| Check | What it finds |
| --- | --- |
| `ec_small_scalar` | An elliptic-curve key whose private scalar k, or n − k, is at most 2^24 + 2^16, on P-224, P-256, P-384 and P-521. Baby-step giant-step over a table of the x-coordinates of 1·G … 2^16·G, built once per curve; about 4 ms per P-384 key. Comparing x-coordinates is what also catches n − k. |
| `rsa_small_factor` | An RSA modulus divisible by a prime below 2^16. |
| `rsa_close_primes` | Two RSA primes so close that Fermat's method factors the modulus within 100 rounds. |
| `rsa_roca` | The ROCA structure (CVE-2017-15361, Infineon RSALib): the modulus lies in the subgroup generated by 65537 modulo each of the primes 3 … 167. |
| `rsa_blocklist` | A key on an operator-supplied blocklist (below). |
| `rsa_public_exponent` | An exponent no RSA key can have: below 3, or even. |
| `rsa_shared_factor` | Two moduli in the same inventory that share a prime (Bernstein's batch GCD). Both can be factored. A key reused by several certificates is one modulus, not a shared factor. Batch GCD is a background routine, never run in a request path, bounded to 20,000 distinct moduli per run. |
| `key_size`, `key_algorithm`, `signature_hash` | When a whole certificate is rated: RSA below 2048 bits, a curve below 256 bits, DSA, or a signature over MD2, MD5 or SHA-1. |

## Operator blocklists

trstctl ships no third-party key list. Debian's 2008 OpenSSL weak-key list
(`openssl-blacklist`) is GPL-3, so the check reads files you supply, in that
package's format: one entry per line, the last 20 hex digits of
`SHA-1("Modulus=" + uppercase hex modulus + "\n")`, `#` comments allowed.

```sh
TRSTCTL_TRUST_WEAK_KEY_BLOCKLIST_FILES=/etc/trstctl/blacklist.RSA-1024,/etc/trstctl/blacklist.RSA-2048
```

The same setting is `trust.weak_key_blocklist_files` in the configuration file.
A missing, empty or malformed file fails startup instead of checking nothing.

## Where the checks run

- **Private keys an agent finds on a host.** Every RSA size and curve is named
  (an RSA-1024 key used to be reported with no algorithm at all). A key below
  the floors, or with a structural weakness, is reported with
  `key_strength: weak`, the reason in `key_weak_reason`, and risk 95 instead
  of 85.

Ratings for discovered, CT-logged, inventory and CBOM certificates, host trust
stores, the signer's key ceremony and the batch-GCD job are what comes next in
this change set; this page grows with each.

## The distrust list

The shipped distrust list (`internal/crypto/trust/distrust.json`) names the
three emSign roots and the eight weak intermediates by public key, and now by
subject key identifier too. A certificate whose authority key identifier names
one of them was issued under it, so a leaf under one of the eight intermediates
is found even when no chain was recorded with it.
